# API Reference

Base URL: `http://localhost:8000`. Full interactive docs (Swagger/OpenAPI)
are auto-generated by FastAPI at `/docs` and `/redoc`.

All error responses follow:
```json
{ "success": false, "error": { "code": "SOME_CODE", "message": "Human readable message" } }
```

## Health

`GET /api/health` → `{ "success": true, "status": "ok" }`

## Orders

- `POST /api/orders` — create a Razorpay TEST MODE order. Body: `{ amount, currency?, receipt?, customer_email?, customer_contact? }` (amount in paise).
- `GET /api/orders` — list recent orders.
- `GET /api/orders/{order_id}` — fetch one order.

## Payments

- `GET /api/payments?status=failed` — list payments, optional status filter.
- `GET /api/payments/{payment_id}` — fetch one payment.

## Recovery

- `POST /api/recovery/analyze` — `{ payment_id }` → OBSERVE+ANALYZE+PREDICT; creates a `RecoveryCase` with an ML score.
- `POST /api/recovery/decide` — `{ recovery_case_id }` → DECIDE+GUARDRAIL; runs the agent, then the policy engine.
- `POST /api/recovery/execute` — `{ recovery_case_id, override_action? }` → ACT+VERIFY+MEASURE; executes the approved action.
- `GET /api/recovery/cases?status=` — list recovery cases.
- `GET /api/recovery/cases/{case_id}` — fetch one case.

## Agent

- `POST /api/agent/analyze` — `{ payment_id }` — convenience endpoint that runs analyze+decide in one call and returns the agent's recommendation, the policy verdict, and reasoning.
- `GET /api/agent/actions` — recent agent actions/decisions, for the AI Agent activity page.

## Dashboard

- `GET /api/dashboard/overview` — revenue at risk/recovered, recovery rate, case counts, agent success rate, avg recovery time.
- `GET /api/dashboard/revenue` — revenue at risk vs recovered only.
- `GET /api/dashboard/recovery-metrics` — recovery rate + agent performance only.
- `GET /api/dashboard/activity` — recent agent-action feed.

## Webhooks

- `POST /api/webhooks/razorpay` — Razorpay webhook receiver. Verifies `X-Razorpay-Signature`
  against `RAZORPAY_WEBHOOK_SECRET`, deduplicates by event id, and for `payment.failed`
  automatically runs the full recovery pipeline (analyze → decide → execute, unless
  the policy engine flags `APPROVAL_REQUIRED`).

## Demo

- `POST /api/demo/simulate` — `{ scenario }` where scenario is one of
  `TEMPORARY_FAILURE | CHECKOUT_ABANDONMENT | REPEATED_FAILURE | HIGH_VALUE_RISKY`.
  Runs the real pipeline against a synthetic transaction and returns the full
  trace (probability, risk, recommendation, policy verdict, execution result).
  Every response and DB row from this endpoint is marked `is_demo: true`.
